# Positioning Strategy: Domain Overview

## The product

Positioning is not a phrase-writing exercise. It is a decision about how a
particular customer should understand an offer relative to what they would
otherwise choose. The domain therefore starts with diagnosis. A good agent must
be able to say, "we do not yet know the real alternative," before it tries to
write a positioning statement.

The central chain is:

`evidence of customer situation -> real alternatives -> differentiated capability -> enabled value -> best-fit customer -> market frame -> expression`

Every link constrains the next. If the alternative is imagined, differentiated
value is invented. If the value is merely asserted, the customer definition is
wishful. If the market frame is chosen first, the whole chain becomes category
theatre.

## Runtime contract

The runtime receives a company evidence card and a question. It first checks
for direct customer evidence: buying triggers, current behavior, stated
alternatives, switching concerns, and evidence quality. It then uses the M1
handbook to return one of three outcomes:

1. a bounded diagnosis with clear evidence and inference labels;
2. a research plan naming the exact missing evidence; or
3. a blocked decision when the question asks for a claim the evidence cannot support.

The runtime slice is deliberately shorter than the handbook. It contains the
relevant diagnostic method, decision rules, case patterns, and source pointers.
It is not an index of IDs and it is not a compressed replacement for the
handbook.
